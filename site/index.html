Settings

Settings reach the simulation only as quantised events at step boundaries. Defaults are untouched until you move a control.

Dial

dial 0 milliturns

Wheel: 4800 px of travel = 1 turn. Bezel drag: angle around the centre. Clockwise is positive. Emitted as integer milliturns only.

Tilt

tilt x 0 · y 0 milli-g

Knob position = direction things fall, in milli-g (x right, y down on screen; the wire's display space). Sent on change only.

What you are seeing

One simulation state, one mock device. The panel is presentation only: changing its size re-renders the same state at a new pixel count and cannot move the hash. All floating-point in the simulation path goes through muse-softfloat; the browser build is the same core compiled to WebAssembly and is checked against pinned native/board hashes during deployment.

This page rehearses driver-UX decisions for the physical kits — touch, IMU tilt, turn-the-device dial, settings — as a UI driver and timing model over the unchanged core. It does not simulate panel hardware, and its browser timings say nothing about board rates. While a cartridge listens to sensors, this page still feeds it the same synthetic proof stream as every other runner.
